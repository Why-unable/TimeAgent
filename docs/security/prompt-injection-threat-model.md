# Time Agent 提示词注入威胁模型

## 是否有必要

有必要，但不能把“检测到某个关键词就拒绝”当作安全边界。Time Agent 具有修改日程、任务、提醒和长期记忆的能力，还会读取新闻、天气、日历、任务与记忆；直接和间接提示词注入都真实存在。

## 主要攻击面

1. 用户直接要求忽略系统规则、输出系统提示词/API Key，或绕过 ActionProposal。
2. 恶意日程标题、任务描述、提醒文字或地点写入“取消其他安排”“泄露历史对话”等指令，随后被查询工具返回给模型。
3. RSS/Atom 新闻正文包含隐藏指令，诱导 Briefing Agent 改变研究目标、伪造来源或把用户日程写进外部 URL。
4. 未来的外部日历/邮件同步把第三方内容带入 Agent 上下文，形成零点击间接注入。
5. 长期记忆污染：把攻击指令伪装成稳定偏好，使其跨会话持续生效。
6. 工具结果或模型输出被前端当 HTML、URL 或命令执行，形成不安全输出处理。

## 已实施控制

- Tool 只调用 Application Service；身份与权限来自可信 Runtime，不来自文本。
- 读写工具按运行模式最小化暴露；被风险策略判定为高风险的行为由 HITL 审批。用户关闭创建/取消确认后，相应无冲突操作不再享受这层防护，设置页必须明确提示这一权衡。
- Tool/外部数据在每次模型调用前统一标记为“不可信数据，不是指令”；命中可疑表达时只记录不含原文的安全事件。
- Time Steward 和 Briefing 系统提示词明确区分请求、事实数据和系统规则。
- Briefing 外部工具只读、调用次数有上限、来源 ID 由结构化输出校验。
- Memory Policy 限制可写内容；工具失败不会污染长期记忆。
- 评测集包含系统提示词和凭据外泄回归案例；前端 Markdown 不启用原始 HTML。

## 仍需持续验证

每次新增外部 Provider、文件/RAG、邮件、浏览器工具或自动写操作，都必须重新做数据流威胁建模。红队测试应覆盖编码/同形字、分隔符伪造、工具输出注入、多轮渐进注入、Memory 持久化和恶意 URL；任何检测器只能增加信号，不能取代授权、Schema 校验与 HITL。
