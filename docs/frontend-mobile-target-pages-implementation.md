# Time Agent 移动端目标页面重构执行规范

## 1. 文档目的

本文档把 `frontend/目标页面/` 中的目标图与补充说明转换为可直接执行的前端重构任务，供后续 coding agent 实施。

本轮只重构移动端页面的信息架构、视觉层级、布局和交互表现，不改变现有业务语义，不重写后端，不更换 React + Capacitor 技术路线。

- `frontend/目标页面/聊天页.png`
- `frontend/目标页面/任务页.png`

## 2. 需求优先级与冲突裁决

材料之间出现冲突时，按以下优先级执行：

1. `frontend/目标页面/readme.md` 中的文字要求；
2. 本文档给出的交互与信息架构约束；
3. 目标图中的布局、比例、视觉层级与风格；
4. 当前代码行为。

目标图底栏同时展示了“日程”和“日历”，但补充说明明确要求二者去重。因此最终实现必须采用以下信息架构：

- 底部主导航只保留：`今天 / 聊天 / 日程 / 更多`；
- 不再保留独立的底部“日历”入口；
- “日程”是统一时间管理工作区入口，默认进入 `/calendar`；
- 日程工作区顶部保留 `日程 / 任务 / 提醒` 三个一级子页切换；
- 日程子页内部再保留 `月 / 周 / 日` 三种日历视图；
- `/tasks`、`/reminders` 路由继续保留，供工作区切换、深链接和浏览器刷新使用。

目标图用于表达产品方向，不要求复制手机状态栏，也不应把截图里的系统状态栏绘制进 Web 页面。

## 5. 移动端统一设计约束

### 5.1 适配范围

- 主要验收宽度：360、390、412、430 CSS px；
- 同时检查 768 px 平板窄屏；
- `lg` 及以上继续使用现有桌面布局；
- 必须适配 Android 状态栏、导航栏和显示挖孔带来的 safe area。

### 5.2 页面骨架

- 页面主体左右内边距：20px；极窄屏可降至 16px；
- 主内容可用宽度应接近全屏，不再套一层狭窄的 `max-width`；
- 底部内容必须预留 `底部导航高度 + env(safe-area-inset-bottom)`；
- 普通页面允许纵向自然滚动；
- 聊天页是例外：消息列表独立滚动，输入区固定在底部导航上方；
- 禁止横向页面溢出；
- 不显示浏览器默认滚动条，但不能因此禁用滚动。

### 5.3 字体层级

目标是达到真正手机 App 的可读性，不能按桌面页面等比例缩小。

- 页面标题：30–34px，字重 650–700；
- 重点数值或主文案：26–32px；
- 区块标题：20–22px，字重 600；
- 正文：16–18px，行高 1.55–1.7；
- 次要正文：15–16px；
- 辅助信息：13–14px；
- 不使用小于 12px 的可见业务文字；
- 中文正文优先使用系统无衬线字体栈，不额外下载字体。

### 5.4 触控与图标

- 所有主要点击目标最小尺寸 48×48px；
- 底部导航单项高度至少 72px，不含 safe area；
- 主要图标 26–30px；
- 次要图标 20–24px；
- 禁止只给一个 14px 图标作为唯一点击区域；
- 删除、取消等危险操作必须保留二次确认。

### 5.5 卡片与层级

- 减少“页面容器 → 大卡片 → 小卡片 → 子卡片”的套娃结构；
- 卡片只用于表达一个独立信息单元，不用于包住整张页面；
- 普通区块可用分隔线和留白组织；
- 主卡片圆角建议 20–24px；
- 次级卡片圆角建议 14–18px；
- 边框应低对比，重点依靠排版、间距和色彩建立层级；
- 青色用于主要操作和当前选中状态；
- 紫色用于提醒；
- 红色只用于错误、冲突和危险操作。

### 5.6 无障碍

- 所有图标按钮必须有 `aria-label`；
- 分段切换使用 `nav` 或具有明确 `aria-label` 的控件；
- 当前页面和当前选项必须有文本、颜色之外的状态表达；
- 弹层必须保留 `role="dialog"`、`aria-modal="true"` 和焦点管理；
- 动画遵守 `prefers-reduced-motion`；
- 深色背景上的普通文字对比度至少达到 WCAG AA。

## 6. 信息架构与路由

### 6.1 移动端底部导航

修改 `frontend/src/layouts/mobile-navigation.tsx`：

| 标签 | 路由 | 图标 | 说明 |
| --- | --- | --- | --- |
| 今天 | `/today` | `Clock3` | 今日概览 |

- 不使用普通 `NavLink` 的单一路由精确匹配来判断该聚合选中状态，应显式读取当前 pathname；
- “更多”内容沿用当前管理员可见性规则；
- 保留 safe-area 处理。

### 6.2 日程工作区顶部切换

修改 `frontend/src/features/workspace/schedule-workspace-tabs.tsx`：

- 三个选项：日程、任务、提醒；
- 对应路由：`/calendar`、`/tasks`、`/reminders`；
- 移动端显示为全宽三段式控件；
- 高度不低于 56px；
- 选中项为实心青色背景和深色文字；
- 未选中项保留足够对比度；
- 三个子页中的位置、宽度和上下间距保持一致；
- 桌面端继续隐藏，除非另有产品要求。

## 7. “今天”页执行要求

目标文件：`frontend/src/pages/today-page.tsx`

### 7.1 页面结构

移动端从上到下：

1. 标题区：时钟图标、“今天”、日期、右上角更多按钮；
2. 今日节奏主卡；
3. 日程 / 任务 / 提醒三个统计值；
4. 今日时间线；
5. 待处理提醒；
6. 存在数据时才显示的任务或冲突信息；
7. 底部导航。

### 7.2 今日节奏

- 使用现有 `TodaySummary` 数据；
- 主标题根据是否存在安排展示“按自己的节奏来”或“今天很轻松”；
- 展示下一项日程的开始时间和标题；
- 右侧圆形/柔和渐变区域展示今日安排数量；
- 若没有下一项日程，显示简短空状态，不留空白占位；
- 不新增后端字段。

### 7.3 统计区

- 三列独立统计：日程、任务、提醒；
- 统计范围保持“今天”，不要改为工作区总量；
- 每列可点击并进入对应工作区子页；
- 不再把统计区嵌套在今日节奏卡内部；
- 数值字号明显大于标签。

### 7.4 今日时间线

- 有数据时使用纵向时间线；
- 左列显示开始和结束时间；
- 中间显示节点及连接线；
- 右列显示标题、类型和地点/项目；
- 事件与计划任务使用不同色彩；
- 每条记录应可点击进入相应编辑流程；若当前 API/组件不支持稳定定位，先保留无跳转展示，并在代码中留下明确 TODO，不得伪造路由；
- 无数据时不要渲染一张占据大量空间的空卡。

### 7.5 待处理提醒

- 只在有数据时显示；
- 每条提醒为紧凑列表项，展示标题、触发时间、进入箭头；
- 点击进入提醒页或对应提醒详情；
- 最多在首页直接展示 3 条，超过时显示“查看全部”；
- 不展示管理员日志字段和投递调试字段。

### 7.6 桌面端

桌面端既有内容可以保留，但应把可复用的数据推导函数抽离，避免移动端和桌面端各自计算不同的统计口径。

## 8. “聊天”页执行要求

目标文件：`frontend/src/pages/chat-page.tsx`

### 8.1 页面骨架

- 顶部栏固定在聊天区域顶部：历史菜单、机器人图标、会话标题、副标题；
- 消息列表占据中间剩余高度并独立滚动；
- 输入区固定在底部导航上方；
- 进入页面时不得自动聚焦 textarea，不得自动弹出手机软键盘；
- 键盘弹出时输入区应跟随 visual viewport，不被键盘遮挡；
- 消息内容在移动端尽量铺满可用宽度，左右仅保留 16–20px 页面边距。

### 8.2 空会话

按目标图实现：

- 中央机器人视觉标识；
- 主文案“今天需要我帮你安排什么？”；
- 一行简短说明；
- 4 个快捷操作：查询日程、整理任务、设置提醒、创建日程；
- 点击快捷操作只填入输入框或提交明确预设文本，行为要一致并有测试；
- 快捷操作在极窄屏允许横向滚动或两列换行，不能挤成不可读的小按钮。

### 8.3 有消息状态

- 保留现有历史加载、SSE、工具状态、审批卡片、Markdown 和时间戳功能；
- Assistant 消息不应被限制在屏幕中间的狭窄卡片中；
- 移动端 Assistant 消息建议使用接近全宽的无气泡或弱背景布局；
- 用户消息保持右对齐气泡，最大宽度建议 82–88%；
- Markdown 表格必须允许局部横向滚动，不能撑破页面；
- 工具调用状态与审批卡片使用全宽内容区；
- 保留“Time Steward 正在处理”状态，但不要造成输入框跳动；
- 取消运行按钮和发送按钮必须保持同一尺寸。

### 8.4 历史抽屉

- 保留现有会话类型分组和新建聊天能力；
- 移动端抽屉宽度建议 86vw，上限 360px；
- 关闭后焦点返回历史菜单按钮；
- 抽屉内触控项高度不低于 48px。

## 9. “任务”页执行要求

目标文件：`frontend/src/pages/tasks-page.tsx`

### 9.1 页面结构

1. 日程 / 任务 / 提醒顶部工作区切换；
2. 简短说明；
3. 全宽“新建任务”主按钮；
4. 任务筛选；
5. 空状态或任务列表。

移动端不再重复显示一个占据大量空间的“任务”页面大标题；当前子页由顶部三段控件明确表达。桌面端可继续显示标题。

### 9.2 筛选

- 第一行优先展示：Inbox、今日任务、即将到期；
- 其他状态放入“更多筛选”或允许横向滚动；
- 当前选中筛选使用实心青色；
- 每个筛选按钮高度至少 48px；
- 不允许为了塞入一行而把文字缩小到 12px 以下。

### 9.3 空状态

- 虚线边框大区域可以保留；
- 空状态图标至少 52px；
- 主文案 20–22px；
- 次要说明 15–16px；
- 文案中的“右上角按钮”需要改为“上方按钮”，因为移动端主按钮是全宽；
- 空状态区域不强制撑满剩余视口，避免形成无意义大空白。

### 9.4 有数据状态

- 保留按项目分组；
- 单条任务应以一眼可扫读为目标：
  - 标题；
  - 状态与优先级；
  - 截止时间；
  - 计划执行区间；
  - 项目/标签；
  - 完成与编辑操作；
- 移动端不要把 `due_at` 等内部字段名暴露给用户；
- 次级信息默认折叠为两行以内；
- 完成和编辑按钮触控区域不小于 48px；
- 已完成任务可弱化并保留删除线。

## 10. “日程”页执行要求

目标文件：`frontend/src/pages/calendar-page.tsx`

### 10.1 页面结构

1. 日程 / 任务 / 提醒顶部工作区切换；
2. 简短时区说明；
3. 全宽“新建日程”主按钮；
4. 月 / 周 / 日视图切换；
5. 日历主体；
6. 点击日期或事件后的当日安排弹层。

移动端不再重复显示一个大号“日历”标题。桌面端标题可保留。

### 10.2 核心滚动规则

必须移除移动端以下固定裁切结构：

- `h-[calc(100dvh-...)]`；
- 页面根节点的 `overflow-hidden`；
- 用一张固定高度卡片包住整个 FullCalendar；
- 仅允许 `.calendar-scroll` 内部滚动的设计。

改为：

- 月、周、日视图完整参与文档流；
- 日历高度由内容决定；
- 内容超出屏幕时由页面纵向自然滚动；
- 月视图至少完整展示六周网格；
- 周视图完整展示设定的日间时间范围；
- 日视图完整展示当天时间轴；
- 事件过多时允许单元格或视图向下扩展；
- 只有确实无法避免的局部内容（如 Markdown 表格）才使用独立滚动。

### 10.3 月视图

- 星期标题使用一、二、三、四、五、六、日；
- 日期格只显示数字，不显示“日”；
- 相邻月份日期降低对比度；
- 当天需要明显但克制的选中样式；
- 事件在格内展示短标题，超长省略；
- 已取消事件不显示；
- 不因事件数量增加而遮住完整月表；
- 保留上月、下月、今天操作。

### 10.4 周视图

- 参考课程表式结构：横向为日期，纵向为时间；
- 日期表头固定清晰，至少展示星期和月/日；
- 时间轴以 30 分钟或 1 小时刻度显示；
- 日程块按开始、结束时间占据真实高度；
- 重叠事件并排展示；
- 移动端可在日列区域横向滚动，但时间刻度列应保持可见；
- 不允许通过极小字体强行塞入七列；
- 事件块点击后打开当日安排弹层。

### 10.5 日视图

- 采用单日纵向时间轴；
- 日程块展示标题、时间、地点；
- 空闲区保持简洁；
- 当前时间指示线可保留；
- 点击空白时间段时，以该时间作为新建日程初始值。

### 10.6 当日安排弹层

保留当前已有能力并统一视觉：

- 点击日期格或事件块打开；
- 列出该日所有未取消日程；
- 每项展示标题、起止时间、地点；
- 每项提供“修改”和“删除”；
- 第一次点删除切换为“确认删除”，第二次才执行；
- 修改后进入现有 `EventEditor`；
- 提供“在这一天新建日程”；
- 移动端用底部 sheet，桌面端用居中 dialog；
- 弹层打开时禁止背景滚动。

## 11. “提醒”页最低一致性要求

目标材料没有单独的提醒页图片，但它属于同一个工作区，必须同步处理：

- 顶部使用相同的日程 / 任务 / 提醒切换；
- 移动端采用全宽“新建提醒”主按钮；
- 不显示 Phase 文案；
- 普通用户历史记录维持当前“最近 10 条”规则；
- 管理员完整历史和诊断能力保持当前权限控制；
- 卡片、字号、触控尺寸与任务页一致；
- 不改动现有提醒创建、取消和投递状态逻辑。

## 12. 建议组件拆分

coding agent 应优先进行以下轻量拆分，避免四个页面继续堆积重复 Tailwind 字符串：

- `MobilePageHeader`：标题、日期/说明、可选操作；
- `MobilePrimaryAction`：全宽新建按钮；
- `ScheduleWorkspaceTabs`：日程/任务/提醒；
- `MobileSegmentedControl`：月/周/日或筛选；
- `MobileSectionHeader`：区块图标、标题、数量、更多；
- `TodayTimeline`：今日时间线；
- `ChatEmptyState`：聊天空状态与快捷操作；
- `TaskEmptyState`：任务空状态；
- `DayAgendaSheet`：当日安排弹层。

组件提取原则：

- 只提取至少复用两次或本身逻辑复杂的结构；
- 不创建只包一层 `div` 的抽象；
- 数据请求继续留在页面/feature hook 层；
- 组件通过明确 props 接收数据，不自行重复请求。

## 13. 样式实现建议

在 `frontend/src/styles/index.css` 中建立少量移动端语义变量，避免每个页面各自猜尺寸：

```css
:root {
  --mobile-page-gutter: 1.25rem;
  --mobile-bottom-nav-height: 5.25rem;
  --mobile-control-height: 3.5rem;
  --mobile-card-radius: 1.5rem;
}
```

要求：

- 不引入新的大型 UI 框架；
- 继续使用 Tailwind + 少量 FullCalendar 覆盖样式；
- FullCalendar 覆盖选择器集中放置并加 `.calendar-shell` 作用域；
- 禁止使用全局 `transform: scale(...)` 放大页面；
- 禁止用固定 `zoom` 解决字号问题；
- 禁止按截图物理像素硬编码 942px 宽布局；
- 背景可以使用轻量 radial-gradient，但不能牺牲文字对比度；
- 动画只用于选中、抽屉和弹层过渡，时长建议 150–220ms。

## 14. 数据与行为约束

- 当前用户时区；
- Today 数据统计口径；
- 创建、编辑和取消日程；
- 创建、编辑和完成任务；
- 创建和取消提醒；
- 聊天会话历史；
- SSE 流式输出；
- 工具调用状态；
- HITL 审批卡片；
- Markdown/GFM 表格；
- Android 原生通知和 Web Push；
- 已取消日程过滤。

若目标图所需展示字段在当前 API 中不存在：

1. 先确认能否由已有字段确定性计算；
2. 可以计算则在 selector/helper 中计算；
3. 不能计算则在本文档之外单独提出 API 变更，不得在前端伪造；
4. 未经确认不要扩大为后端重构任务。
