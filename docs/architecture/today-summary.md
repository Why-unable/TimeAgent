# Today 汇总

`GET /api/v1/today/` 返回当前认证用户的结构化每日工作台。汇总由 `TodayService`
生成，前端不自行判断任务分桶或时间冲突。

## 日界线与分类

- “今天”由 `UserPreference.timezone` 和请求时刻共同确定；
- 日区间使用 `[本地零点, 下一日本地零点)`，转换为 UTC 后查询，因此 DST 切换日可以是
  23 或 25 小时；
- 日程按与今日区间重叠查询，取消日程不进入汇总；
- 今日计划任务按计划区间与今日重叠查询；
- 今日截止任务的 `due_at` 位于今日半开区间内；
- 已逾期任务的 `due_at` 早于今日零点，和今日截止任务保持互斥；
- 已完成、已取消任务不进入上述活动任务集合；
- `unfinished_tasks` 是上述今日活动任务与进行中任务的去重并集；`completed_tasks` 只包含今日完成的任务；
- 待处理提醒仅包含今日触发且尚未进入终态的提醒。

## 今日执行面

`execution_now`、`execution_next`、`execution_later` 是 `TodayService` 根据请求时刻和用户时区
生成的执行分组。前端直接展示分组，不用本地时钟重新分类。Now 包含当前时间重叠的日程和进行中任务；
Next 包含最早的后续开始时刻上的事项；Later 包含其余未来安排、未完成但计划时段已过的任务，以及
今日截止或已逾期且尚未安排的任务。已完成和已取消任务不进入执行分组。

## 明日草案

Day Closing 只把用户明确勾选的未完成任务提交给 `plan_tasks_only`。范围按用户时区的明日零点至
后日零点计算，数据库时间仍为 UTC。草案创建请求可以带 `operation_id`；相同用户以相同请求重试时
返回既有草案，重复键对应不同请求时拒绝，唯一约束与用户级 schedule-write advisory lock 共同
避免并发重复草案。草案不是正式任务安排，必须从 Planning 经既有 HITL 流程另行提交应用。

若有任务未安排，响应仍保留其未安排项。用户可以保留草案，也可以明确放弃该草案后重新选择；放弃只
改变草案状态，不删除任务或修改任务截止时间。

晨间简报由用户显式点击调用 Briefing Run API 并进入 Briefing Workflow；Today 不自动启动模型，
也不先经过 Time Steward Agent。

## 冲突与下一日程

冲突检测以日程和计划任务组成统一的时间区间集合，返回发生重叠的两个结构化项目及重叠
区间。相邻但不重叠的半开区间不是冲突。前端仅展示服务端结果。

“下一个日程”是今日尚未开始的最早非取消日程，`minutes_until_next_event` 使用向上取整的
分钟数；今天没有后续日程时两个字段均为 `null`。

天气与待审批操作仍由其独立的现有功能提供；晨报通过 Briefing Run API 提供，不在 Today 汇总中
复制简报业务规则或伪造空业务契约。
