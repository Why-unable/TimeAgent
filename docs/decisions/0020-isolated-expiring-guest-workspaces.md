# ADR 0020：隔离且自动过期的游客工作空间

状态：已采纳
日期：2026-08-10

## 背景

公开演示需要让访客无需提交邮箱即可体验主要功能。单一共享账号会导致日程、聊天、
提醒和记忆相互可见，也会引入并发覆盖、隐私泄露和模型费用滥用风险。

## 决策

1. 每个首次进入的浏览器或 Android 安装创建独立 Django 用户，并通过 `GuestAccount`
   记录过期时间。网页继续使用 Session，Android 继续使用 Keystore 中的 DRF Token。
2. 同一浏览器在有效 Session 内复用同一游客账号；不同浏览器、无痕窗口、清除数据、
   主动退出或过期后创建新账号，不提供共享游客凭据。
3. 游客账号没有邮箱和可用密码。API 明确返回游客身份和过期时间，界面持续提示临时性。
4. 游客创建由独立的匿名 IP 限流保护；Agent 请求以及会话、日程、任务和提醒均设置
   服务端配额。配额检查位于 Application Service，不依赖前端判断。
5. 游客禁用长期记忆、定时简报、邮件通知和 Web Push，仅允许应用内提醒。账号创建时
   通过现有 Application Service 写入少量带“示例”标识的数据。
6. Celery Beat 周期性停用过期账号，删除其 LangGraph checkpoint、长期记忆和 Django
   用户；业务表继续依靠现有用户外键级联删除。
7. 游客模式由 `GUEST_ACCESS_ENABLED` 显式开启，默认关闭。相关 TTL、频率和资源配额
   均由服务端环境变量配置。

## 结果与限制

- 游客之间的数据和认证凭据完全隔离，不会出现共享账号的数据串扰。
- 退出游客账号后无法恢复原临时空间；将游客数据升级为正式账号不在本次范围内。
- 应用层限流不能替代边缘防护。公开部署仍应在 Cloudflare 配置 WAF、Bot 防护和按路径
  限速，并监控游客创建量、Agent 请求量与模型 Token 消耗。
