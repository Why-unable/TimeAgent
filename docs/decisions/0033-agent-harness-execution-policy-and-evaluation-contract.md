# ADR 0033：Agent 工具执行授权与排程评测契约

- 状态：已接受；候选实现须通过真实模型回归与 sealed hold-out 后才可用于发布决策
- 日期：2026-09-28

## 背景

Time Steward 由 LangChain `create_agent()` 驱动，运行时注册完整 Tool Registry，再按请求构造较小的工具面。仅裁剪传给模型的 schema 不能构成执行授权：模型或恢复流程仍可能提交未暴露的工具调用。另一个评测问题是把 fixture 的搜索窗口误当成用户提出的日期约束，也把只读请求按“必须生成计划”计分，导致评测器与产品语义不一致。

## 决策

1. 保留单个 `create_agent()` Time Steward。外层工作流负责路由、中断恢复及确定性调度；不因本轮问题新增 Planner/Critic/Supervisor Agent。
2. 请求策略须同时产出 `hard_allowed_tools` 与 `visible_tools`。可见列表用于减少工具选择负担；`hard_allowed_tools` 是执行授权边界。
3. 同一策略函数用于模型工具表和同步/异步真实工具执行路径。执行中间件在业务 handler 前重新核验工具权限。未知工具不得触发未校验 registry 查找；隐藏但仍获硬授权的工具调用应被拒绝并以结构化错误显式恢复，硬禁止工具应失败关闭。
4. `read_only` 同时限制执行路径，任何会改变业务事实或创建持久化草案的 Tool 都不得执行。高风险变更仍须经过 ActionProposal 与 HITL；Agent 评测不自动批准。
5. 排程服务接收明确的运行时 `now`，新候选开始时间不得早于该锚点。评测器的通用搜索窗口只限定合成数据生成范围；只有由用户原话证实并带来源引文的 `user_requested_range` 才计为用户范围硬约束。
6. 评测按请求意图分别判定计划、只读回答、澄清、审批等待和重排提议。确定性 baseline 不读取 evaluator-only expectations；只读/澄清场景可以不适用 baseline，不能伪装成失败或成功。
7. 已经查看并用于调优的数据集一律归入 Regression Set。新的 hold-out 由未读取具体 regression/prompts 的独立生成者产生并冻结；一旦查看某条并据此调整候选，该条即降级为回归并须生成 replacement。
8. 仅将脱敏的结构化轨迹、指标与匿名评审结果提交到版本库。原始模型文本、任务事实、凭据、用户标识与私有推理不进入共享 Artifact。

## 结果与验证要求

- 执行策略和运行锚点已有单元/集成回归覆盖；全后端测试、静态检查、Django 检查与迁移漂移检查作为候选代码质量门。
- 本 ADR 不代表候选已达到发布标准。真实模型回归、独立 sealed hold-out、多运行尾部风险、盲评和效率门槛仍须有可复核 Artifact 支持。
- 若真实模型不可用，评测应明确失败或标为未运行，不得以 mock、旧报告或 baseline-only 结果代替 Agent 质量结论。

## 后果

该边界让 LLM 继续负责语义理解、偏好权衡、阶段判断及何时澄清，同时由服务层和执行策略守住事实、权限、冲突、时区、版本与 HITL。代价是评测 fixture 要额外标注意图和可追溯的用户范围契约，不能再用无来源的宽泛期望约束 Agent。
