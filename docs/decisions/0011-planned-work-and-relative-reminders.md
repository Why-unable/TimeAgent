# ADR 0011：计划事务与相对提醒

## 背景

任务和日程是不同的业务事实：任务表达待完成的工作，日程表达占用某段时间。用户需要一个任务关联多条日程，并希望在任务计划开始时间或日程开始时间改变时，相关提醒随之调整。

## 决策

1. `CalendarEvent.task` 是可选外键；一个任务可拥有多条日程，日程也可以不属于任何任务。
2. 计划任务以 `planned_start_at` 为锚点，自动维护提前 7 天、3 天、1 天和 30 分钟的未来提醒；日程以 `start_at` 为锚点，自动维护提前 1 天、2 小时和 30 分钟的未来提醒。
3. 自动提醒在 Reminder 中保留目标、锚点和偏移量；稳定去重键由目标与偏移量组成。它们仍由既有的确定性 Celery Reminder Dispatcher 投递，不进入 LLM。
4. 任务重排、完成、取消以及日程更新、取消都只能经 Application Service 调用 `ReminderScheduleService` 同步或取消未完成的自动提醒。
5. 用户手工创建的提醒可以关联任务、日程或不关联；手工提醒不被自动同步服务修改。
6. Agent Tool 只调用 Task/Event/Reminder Application Service。创建任务可携带计划时间，创建日程可带 `task_id`，创建手工提醒可带目标；取消操作继续遵循既有 HITL 风险策略。

## 后果

- 时间变更与提醒时间保持一致，同时保留已投递提醒的审计历史。
- 已经过期的相对触发点不会在重排时补发；只维护未来触发点。
- 自动提醒的默认偏移是保守的个人时间管理默认值，不会替代用户将来可配置的逐条提醒策略。
